# 设计与实现说明

本文档描述 `kindle-pdf-cropper` 的处理流水线、算法与关键实现决策。

## 1. 总体流水线

```
输入 PDF
  │
  ▼
normalize_work_doc()         把每一页的 /Rotate“烘焙”进内容（remove_rotation），
                             统一坐标系 = 显示方向；页面内容原样复制（insert_pdf）
  │
  ▼
Pass 1: 逐页特征提取         渲染灰度位图 → 二值墨水掩码(8×8 块) → 行/列投影；
                             同时提取文本行 bbox/字号、图片框、是否扫描页
  │
  ▼
Pass 2: 全局页眉/页脚判定     跨页统计“重复出现的顶部/底部文本行”（运行页眉/页脚）；
                             逐页结合墨水带间隙启发式，确定 header/footer 裁剪带
  │
  ▼
crop 计算                    从“正文带”投影求内容框，加 padding，
                             排除页眉/页脚带，得到每页裁剪矩形
  │
  ▼
split（可选）                沿水平中轴切为上下两页，两页在切点附近重叠
  │
  ├──► PDF 输出                show_pdf_page(clip) 物理裁剪，文字/矢量/图片保真
  └──► EPUB 输出               固定版式 EPUB3：SVG 页（文字页）/ 位图页（扫描页）
```

## 2. 坐标系统一（关键）

PDF 页面可能带 `/Rotate`（扫描件常见 90°/270°）。PyMuPDF 的 `get_text()`、
`get_image_info()` 返回**未旋转坐标**，而渲染位图是**旋转后的显示坐标**，
两者直接混用会错位。解决办法：

1. `work.insert_pdf(src)` 原样复制页面（保留 /Rotate 与 CropBox）；
2. 对每页调用 `Page.remove_rotation()`，把旋转烘焙进内容；
3. 此后 `page.rect`、渲染位图、文本 bbox 三者使用同一套坐标 = 显示方向，
   裁剪矩形可以直接用于渲染和 `show_pdf_page(clip)`。

## 3. 逐页分析（Pass 1）

### 3.1 渲染与二值化
- 以 `--analysis-dpi`（默认 144）渲染为灰度图；大页面自动降 DPI，最长边不超过 2600px；
- 3×3 中值滤波去除扫描噪点；
- **中点法二值化**：取直方图两个主峰（背景峰、最暗内容峰）的中点作为阈值。
  这是有意不用 Otsu——文档型页面中“纯黑文字核心”的小峰值会主导 Otsu 的类间方差，
  导致阈值错误地取到 0（实测发生）。中点法对“白底黑字 / 灰底黑字 / 浅字”都稳定；
- 暗底页面（负片扫描）自动反相；
- 按 8×8 像素块做 `any()` 降采样得到块级墨水掩码，行/列投影基于块，抗噪又省内存。

### 3.2 文本/图片元数据
- `get_text("dict")`：逐行合并 span，得到行 bbox、字号、归一化文本
  （去符号只留字母数字，用于跨页重复检测与页码识别）；
- `get_image_info()`：图片框与总面积占比；
- 页面分类：`图片面积 ≥ 50% 页面积且文本字符 < 300` → 扫描页；
  文本页/混合页照常走同样的栅格分析。

## 4. 页眉/页脚与页码（Pass 2）

### 4.1 全局重复检测（运行页眉/页脚）
- 收集所有页顶部 12% / 底部 12% 区间的文本行；
- 排除“页码样式”的行（见 4.2）；
- 统计 `(顶部/底部, 归一化文本)` 出现页数，出现 ≥ `max(2, 30%·总页数)` 视为运行页眉/页脚。

### 4.2 页码识别
正则匹配 `- 12 -`、`42`、`Page 12`、`— iii —`、`第 12 页` 等常见形式
（去装饰符后为纯数字、罗马数字或 `Page/第…页` 前缀 + 数字）。

### 4.3 逐页带检测
两条信号，任一命中即裁掉：

1. **文本信号**：候选行（重复页眉/页脚 或 页码样式）与正文之间必须有 ≥
   `0.6 × 中位行高` 的空白间隔，防止误删紧贴正文的行；
2. **几何信号**（扫描页主力）：行投影分组后，若页边缘存在“小带（≤7% 页高）且与
   下一个正文组之间有大于正文组间中位间隔的空白”，则视为页眉/页脚带；
   并对带边界做“任意墨水”扩张（上限 1.5% 页高），避免页码字头细笔画被漏掉。

安全阀：总裁剪高度 ≤ 25% 页高；裁剪后任一边小于 15% 页长则放弃该页裁剪
（保护近空白页/异常页）。

## 5. 裁剪矩形

- 纵向：从页眉带之下/页脚带之上的**第一个/最后一个有墨水的行**出发；
- 横向：只统计**正文行带**内的列投影（页角页码、运行页眉不会撑宽裁剪框）；
- 用文本行 bbox、非整页图片 bbox 扩充框体（防止过细/过淡内容被裁）；
- 加 `--padding`（默认 6pt）安全边距后夹在页面内。

## 6. 切分（--split）

- 沿裁剪矩形的水平中轴切成上、下两页；
- 重叠量 = `max(3% × 裁剪高, 20pt)`（默认值，可用参数调整），保证中线附近的一行
  在上下两页都能完整显示；
- 输出页宽 = 原页宽、页高 ≈ 原裁剪高的一半 → 天然横版（landscape），
  文字仍保持水平方向，Kindle 横屏时字号相当于翻倍。

## 7. PDF 输出

- 对每个输出段新建一页，尺寸 = 裁剪尺寸；
- `show_pdf_page(page.rect, work, src_pno, clip=裁剪矩形)`：
  把源页内容按裁剪区“物理复制”过来。因为是 Form XObject 引用，
  **文字仍是可选中的文字，矢量（表格线/公式路径）和嵌入字体原样保留，图片不重采样**；
- 保留元数据；目录按 `源页 → 输出页` 映射重写。

## 8. EPUB 输出（固定版式）

- EPUB3 `rendition:layout=pre-paginated` + `rendition:orientation=auto`
  + Apple Books `display-options.xml`；
- 每页一个 XHTML，viewport 元数据 = 该页像素尺寸；CSS 用 `width/height:100%` 撑满；
- 页面策略：
  - `--epub-mode svg`：`get_svg_image(text_as_path=False)` 内联 SVG，
    文字保持为 `<text>`，矢量图保持路径，图片 base64 内嵌；
  - `--epub-mode image`：整页 JPEG/PNG 位图（灰阶自动转 L 通道减小体积）；
  - `--epub-mode auto`（默认）：文字页 → SVG，扫描页 → 位图；
- 首段生成封面图；EPUB 校验：`mimetype` 必须是无压缩的首个条目，OPF manifest/spine
  与 zip 内容一致（测试覆盖）。

## 9. 调试辅助

`--debug-dir DIR` 会为每一页输出一张叠加图：
红色 = 被裁掉的页眉/页脚带，绿色 = 最终裁剪框，蓝色 = 切分后的各段框。
调参（padding、zone、gap 系数等）时可直观对照。

## 10. 已知限制与后续方向

- 双栏/多栏论文只会整体裁剪，不会拆栏（需求限定“只做整体裁剪和切分”，故符合）；
- 扫描页若自带黑色边框/装订阴影，需更大的 `--padding` 或先做去边预处理；
- 旋转 90° 的扫描页：页眉/页脚随页面旋转到左/右边缘，目前靠横向边距裁剪覆盖，
  不做列向带检测；
- SVG 页依赖阅读器对 SVG 的支持（Kindle 对固定版式支持有限，建议 Kindle 用户
  使用 PDF 输出或 `--epub-mode image`）；
- 后续可加：OCR 文字层（对接 OCRmyPDF/Tesseract）、斜校正、装订阴影去除、
  多进程并行分析、页眉/页脚自定义区域。
